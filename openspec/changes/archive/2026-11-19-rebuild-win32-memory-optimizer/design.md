## Context

现有仓库包含样本、截图与反编译产物。`decompiled/memory_optimizer.core.c` 中的 `CleanMemoryAndMeasure`、`AutoOptimizationWorker`、`RefreshMemoryDisplay` 和 `MainWindowProc` 是行为参考。原样本的清理结果取决于全系统内存读数，且手动按钮在窗口消息处理函数中同步执行清理。

当前工作站已发现 VS Build Tools 2022、MSVC、Windows SDK 和支持 `Visual Studio 17 2022` 生成器的 CMake。首轮运行验收以当前 Windows x64 环境为准。

## Goals / Non-Goals

**Goals**

- 从应用源码独立构建 x64 GUI 可执行文件，普通用户可以运行。
- 提供中文内存监视、托盘、悬浮窗、手动清理和自动清理。
- 保证清理期间窗口继续响应，显示真实的 API 结果及全系统可用物理内存净变化。

**Non-Goals**

- 待机列表清理和其他需要专门兼容性验证的系统级操作归入后续独立变更。
- 精确重现样本外观、原始工程和第三方链接属于独立范围。本项目提供独立布局与资源。

## Decisions

1. **C++17、Win32 Unicode 和 CMake。** 应用使用 `wWinMain` 与 Windows GUI 子系统，中文源码以 UTF-8 构建。仓库提供 `CMakeLists.txt` 和文档，支持 MSVC x64 Release 构建，Windows 资源通过 SDK 的资源编译器构建。构建目标只引用新源码和资源。
2. **界面线程拥有窗口和调度状态。** `WM_TIMER` 每秒刷新读数并评估触发，悬浮窗重用本轮物理内存快照。主窗口的状态与清理状态分别记录。托盘负责恢复窗口和退出。托盘图标注册失败时保留可见窗口。
3. **单次清理在后台执行。** 手动和自动请求使用同一入口。界面线程在派发前占用清理状态，工作线程发布结果后通过 `WM_APP` 通知，界面线程消费结果并释放状态。工作线程只采样、执行和发布，由界面线程更新控件。停止自动优化会撤销后续自动触发。退出时停止派发，执行中的清理在进程边界响应取消，完成后由界面线程收尾并销毁资源。
4. **用单调时钟驱动两个独立条件。** 启动自动优化时校验并快照配置，启用期间锁定输入框。阈值、间隔与冷却默认分别为 `80%`、`60` 分钟、`30` 分钟。每次实际开始清理均记录时间，用于约束阈值触发。定时从启用时起算，观察到到期就用当前时间加间隔设置下一次到期。手动与阈值触发保留定时进度，两个条件同时满足时合并，正在清理时到期也消化本次到期且不积压任务。策略由可注入的时间、采样值和执行状态驱动。
5. **区分采样、API 结果与展示。** `GlobalMemoryStatusEx` 提供物理内存，`GetPerformanceInfo` 提供提交量、提交上限和系统缓存页数。工作集后端用 Toolhelp 枚举进程，用 `PROCESS_SET_QUOTA` 和 `PROCESS_QUERY_LIMITED_INFORMATION` 请求访问，再调用 `EmptyWorkingSet`。用 RAII 关闭快照与进程句柄，记录裁剪成功、跳过、失败和枚举是否完整。系统可用物理内存采用清理后减清理前的带符号净差，任一侧采样失败时提供明确的缺失状态。界面保留最近完成的执行结果和时间。

## Risks / Trade-offs

- 进程可能退出或受保护 → 对单个进程失败按类别计数并继续。枚举中断时显示结果范围。
- 工作集可能回升，系统净变化也会受其他进程影响 → 分开显示 API 结果与采样变化，以受控子进程验证工作集操作。
- 窗口可能在清理时退出 → 关闭阶段保持消息循环和结果存储有效，等工作线程结束再销毁状态。
- 输入非法或系统采样短暂失败 → 校验完整输入，显示可修改的错误提示。缺失的物理内存读数只暂停阈值判断，定时条件继续工作。

## Migration Plan

以新建应用目标构建和验证，在输出目录生成独立的 x64 可执行文件。直接从构建产物启动，无需导入旧配置。
