# memory-monitoring-and-trimming Spec

## Purpose

定义 Windows 物理内存、系统提交量与系统缓存的采样方式，以及当前用户权限下的进程工作集裁剪。规定成功、跳过和失败的统计方式与可用物理内存净变化的计算规则。

## Requirements

### Requirement: 分别获取物理内存和性能数据

应用 SHALL 从 Windows 系统采样物理内存的总量、可用量及使用率，并从性能信息读取系统提交量、提交上限及系统缓存页数。应用 SHALL 将性能页数转换成容量，并保留每类采样的有效状态。

#### Scenario: 采样值转换为界面快照

- **WHEN** 两类 Windows API 均提供有效数据
- **THEN** 快照包含按实际字节量计算的物理内存用量、提交量、提交上限和系统缓存容量，以及系统报告的物理内存使用率

### Requirement: 用当前用户权限裁剪进程工作集

应用 SHALL 使用公开工作集 API 尝试清理当前权限可访问的进程。应用 SHALL 在某进程退出或无法打开时继续处理其余进程，按成功、跳过、失败统计结果。应用 SHALL 标示枚举失败、中断或退出取消等导致结果不完整的情况。

#### Scenario: 进程访问权限不一致

- **WHEN** 枚举得到一个可以打开且裁剪成功的进程、一个拒绝打开的进程和一个打开成功但裁剪失败的进程
- **THEN** 结果分别记录一次成功、一次跳过和一次失败，完成后各资源句柄均已释放

#### Scenario: 无法完成进程枚举

- **WHEN** 快照创建失败或枚举提前结束
- **THEN** 结果标示未完成，并保留本次已处理进程的计数

### Requirement: 单独报告可用内存净变化

应用 SHALL 以清理后可用物理内存减去清理前可用物理内存计算带符号净变化。应用 SHALL 独立展示净变化与工作集裁剪结果。任一侧采样失败时，应用 SHALL 将净变化标为不可用。

#### Scenario: 清理后可用内存下降

- **WHEN** 工作集 API 对至少一个进程调用成功，但清理后采样的可用内存比清理前少 `64 MiB`
- **THEN** 结果保留裁剪成功计数，并显示可用内存净变化为负 `64 MiB`

#### Scenario: 清理后采样缺失

- **WHEN** 工作集裁剪完成后无法获得有效的物理内存采样
- **THEN** 应用显示执行计数及时间，将净变化标为不可用
